# v1.2.4 — DST-safe UTC storage with fast Berlin statistics

Includes the UTC storage and audited database migration fix for issue #47.
Dashboard presentation, calendar statistics and daily filenames remain in
Europe/Berlin. Containers and stored/API measurement timestamps use UTC.

Berlin timezone transitions are compiled from ZoneInfo into native SQLite date
arithmetic once per connection. Full-history statistics no longer invoke Python
for every measurement. Calendar range queries retain the timestamp index.

Migration preserves mixed historical UTC/local timestamps through documented
source-timezone ranges, explicitly resolves repeated autumn hours, retains IDs
and measurement values, and records original timestamps in an audit table.

**Existing databases must be migrated to schema 3 before starting these images.**
See [migration and rollback instructions](../utc-migration.md).

32 regression tests cover timezone boundaries, native SQL/ZoneInfo equivalence,
index use, data preservation, migration failure handling and atomic JSON import.
